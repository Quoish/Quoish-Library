# SPI通信
SPI（Serial Peripheral Interface，串行外设接口）是一种由控制器提供时钟的同步串行通信方式，常用于单片机与传感器、显示屏、ADC、DAC、Flash和无线通信芯片之间的短距离高速通信。

SPI没有统一规定命令、地址和数据帧的含义。通信双方只依照时钟逐位交换数据，寄存器地址、读写位、校验方式和片选时序由具体器件的数据手册规定。

## SPI的信号线
标准四线SPI包含以下信号：

- `SCK`或`SCLK`（Serial Clock）：串行时钟，由控制器产生
- `COPI`（Controller Out, Peripheral In）：控制器输出、外设输入，传统名称为`MOSI`
- `CIPO`（Controller In, Peripheral Out）：控制器输入、外设输出，传统名称为`MISO`
- `CS`、`SS`或`NSS`（Chip Select）：片选信号，由控制器选择当前通信的外设

许多芯片手册和库仍使用Master/Slave及MOSI/MISO命名，因此阅读资料时需要同时认识两套术语。

最常见的一对一连接方式为：

```text
控制器                         外设
SCK   ----------------------> SCK
COPI  ----------------------> COPI / MOSI / SDI
CIPO  <---------------------- CIPO / MISO / SDO
CS    ----------------------> CS / SS / NSS
GND   ----------------------- GND
```

信号名称要从器件在本次通信中的角色理解。例如控制器的`COPI`应连接外设的数据输入端，控制器的`CIPO`应连接外设的数据输出端。

### 片选信号
多数SPI外设的片选为低电平有效：

1. 控制器把目标外设的CS拉低
2. 控制器产生SCK并交换数据
3. 一帧事务完成后，控制器等待最后一个时钟结束
4. 控制器把CS拉高

CS的有效电平、建立时间、保持时间以及一帧中能否短暂拉高，都应以外设数据手册为准。有些器件利用CS上升沿锁存命令，有些器件则允许CS持续为低并连续传输多个字节。

CS在上电和控制器复位期间不应意外选中外设。必要时可增加上拉电阻，使CS在GPIO尚未初始化时保持无效状态。

## SPI的传输原理
SPI控制器和外设内部都可以看作一个移位寄存器。每出现一个时钟周期，双方各移出一位，同时各接收一位。因此标准四线SPI天然支持全双工通信。

```text
控制器移位寄存器  --COPI-->  外设移位寄存器
控制器移位寄存器  <--CIPO--  外设移位寄存器
                         ^
                         |
                        SCK
```

传输一个8位数据通常需要8个时钟周期。控制器发送一个字节的同时，也会收到一个字节：

- 写寄存器时，接收到的数据可能没有意义，但仍需要及时读取，避免接收缓冲区溢出
- 读寄存器时，控制器必须继续发送占位数据来产生时钟，常用占位值为`0x00`或`0xFF`
- 一些外设在收到命令后需要额外的空周期，读取数据前需要发送一个或多个Dummy Byte

SPI本身没有应答位、地址仲裁或重传机制。控制器无法仅凭硬件传输完成判断外设是否存在，也无法确认外设是否正确理解了命令。需要根据器件协议读取状态寄存器、芯片ID或数据校验结果。

## 时钟极性和时钟相位
SPI使用CPOL和CPHA决定时钟空闲电平以及在哪个边沿采样数据。

### CPOL
- `CPOL = 0`：SCK空闲时为低电平，第一个边沿为上升沿
- `CPOL = 1`：SCK空闲时为高电平，第一个边沿为下降沿

### CPHA
- `CPHA = 0`：在每个时钟周期的第一个边沿采样，在第二个边沿改变数据
- `CPHA = 1`：在每个时钟周期的第一个边沿改变数据，在第二个边沿采样

四种SPI模式如下：

| SPI模式  | CPOL | CPHA | SCK空闲电平 | 采样边沿 | 数据改变边沿 |
| ------ | ---- | ---- | ------- | ---- | ------ |
| Mode 0 | 0    | 0    | 低       | 上升沿  | 下降沿    |
| Mode 1 | 0    | 1    | 低       | 下降沿  | 上升沿    |
| Mode 2 | 1    | 0    | 高       | 下降沿  | 上升沿    |
| Mode 3 | 1    | 1    | 高       | 上升沿  | 下降沿    |

通信双方必须使用相同模式。模式错误时，常见现象包括数据整体左移或右移一位、最高位不稳定、固定读取到错误值，以及降低时钟频率后偶尔能够工作。

在`CPHA = 0`的模式中，第一个数据位需要在第一个采样边沿到来前已经稳定。因此拉低CS后，到第一个SCK边沿之间通常需要满足器件规定的建立时间。

## 数据帧与位序
SPI每次传输的数据单元常见为8位或16位，部分控制器支持4至32位等其他长度。

- MSB First：最高有效位先传输
- LSB First：最低有效位先传输

位序只规定一个数据单元内部各位的先后顺序。一个16位或32位数由多个8位数据组成时，先传高字节还是低字节仍由外设协议决定，不能只依赖控制器的MSB/LSB设置。

例如一个器件要求依次发送16位寄存器值`0x1234`的高字节和低字节：

```c
uint8_t tx_data[2] = {
  (uint8_t)(value >> 8),
  (uint8_t)value
};
```

## 通信方向
### 全双工
使用SCK、COPI和CIPO，发送和接收同时进行。标准四线SPI最常使用这种方式。

### 单工
数据只沿一个方向传输。例如仅写入的显示屏可以不连接CIPO，但这会失去读取状态或芯片ID的能力。

### 半双工
发送和接收共用一根双向数据线，也称三线SPI。控制器需要在适当时间切换数据线方向，并避免双方同时驱动总线。

半双工中的“三线”通常是SCK、双向数据线和CS，不应与不带CS的特殊接口混淆。

## 多外设连接
多个SPI外设通常共享SCK、COPI和CIPO，每个外设使用独立的CS：

```text
                    +---- 外设A
SCK  ---------------+---- 外设B
COPI ---------------+---- 外设C
CIPO ---------------+---- 外设A/B/C共同返回

CS_A -------------------- 外设A
CS_B -------------------- 外设B
CS_C -------------------- 外设C
```

未被选中的外设必须让CIPO进入高阻态，否则多个外设会同时驱动CIPO，产生总线冲突。如果器件不能正确释放数据线，可以使用三态缓冲器、模拟开关或独立SPI接口隔离。

同一总线上的不同外设可以使用不同的时钟频率、CPOL、CPHA和位序。每次拉低目标CS之前，应先切换为该外设所需的配置；释放CS后再结束本次事务。

另一种连接方式是菊花链：前一个器件的数据输出连接后一个器件的数据输入，所有器件共用CS。菊花链需要器件本身支持，常见于移位寄存器和部分DAC，不能默认用于普通SPI外设。

## SPI时钟频率
控制器通常使用外设时钟经过预分频产生SCK：

$$f_{SCK}=\frac{f_{SPI\ source}}{Prescaler}$$

实际可用频率同时受到以下因素限制：

- 外设数据手册给出的最大SCK频率
- 控制器SPI模块的最高频率
- 外设对CS建立时间、数据建立时间和保持时间的要求
- PCB走线、排线长度、负载电容和电平转换器速度
- 中断或软件轮询能否及时取走接收数据

调试新设备时可以先使用较低时钟频率，确认模式和命令正确后逐步提高。提高频率后出现偶发错误，通常需要检查波形完整性、返回数据延迟和时序裕量。

## 常用配置参数
- 工作角色：控制器或外设
- 通信方向：全双工、单工或单线半双工
- 数据长度：常见为8位或16位
- 时钟极性CPOL
- 时钟相位CPHA
- 位序：MSB First或LSB First
- 时钟分频：决定SCK频率
- 片选管理：硬件NSS或软件GPIO控制
- CRC：部分控制器支持硬件CRC，但必须与外设协议一致
- TI帧格式：部分控制器支持，不等同于普通Motorola SPI格式

软件管理CS更加灵活，适合大多数传感器、Flash和显示屏。硬件NSS是否能产生外设需要的片选波形取决于控制器实现，使用前应核对参考手册。

## 一次SPI事务的基本流程
下面的伪代码展示了常见的寄存器读取流程：

```c
spi_configure(clock, mode, bit_order);
gpio_write(CS, LOW);

spi_transfer(read_command);
spi_transfer(register_address);
value = spi_transfer(dummy_byte);

wait_until_spi_not_busy();
gpio_write(CS, HIGH);
```

其中命令格式、读写位的位置、寄存器地址长度和Dummy Byte数量都由外设决定。

释放CS前不能只判断发送缓冲区为空。发送缓冲区为空通常只代表最后一个数据已经进入移位寄存器，还应等待SPI总线的Busy状态结束，确保最后一个时钟已经发出。

## 轮询、中断和DMA
### 轮询方式
CPU等待每个数据单元完成，流程最直观，适合初始化、少量寄存器访问和低频通信。

### 中断方式
函数启动传输后立即返回，由发送空、接收非空和错误中断推进传输。适合数据量中等、主程序还需要处理其他任务的场景。

### DMA方式
DMA在内存和SPI数据寄存器之间搬运数据，适合屏幕刷新、音频流、采样数据和大块Flash读写。

使用DMA时需要注意：

- 发送和接收缓冲区必须在传输完成前保持有效
- 全双工通信通常需要同时配置TX DMA和RX DMA
- 只发送时也要处理可能产生的接收数据，具体方式取决于控制器
- 循环DMA适合连续数据流，普通寄存器事务通常使用正常模式
- 带数据缓存的处理器需要处理Cache一致性
- CS应在真正传输完成后释放，不能在DMA启动函数返回后立即拉高

可结合[[中断和DMA]]了解缓冲区生命周期、回调和共享数据处理。

## STM32 HAL示例
STM32 HAL常用的SPI传输函数包括：

```c
HAL_SPI_Transmit()
HAL_SPI_Receive()
HAL_SPI_TransmitReceive()

HAL_SPI_Transmit_IT()
HAL_SPI_Receive_IT()
HAL_SPI_TransmitReceive_IT()

HAL_SPI_Transmit_DMA()
HAL_SPI_Receive_DMA()
HAL_SPI_TransmitReceive_DMA()
```

阻塞函数在传输完成或超时后返回；中断和DMA函数只负责启动传输，完成后进入对应回调。其调用模式与其他HAL外设一致，可结合[[HAL库常用函数]]中的阻塞、中断和DMA约定理解。

下面假设某器件使用寄存器地址最高位表示读取，读取一个寄存器需要发送地址后再发送一个Dummy Byte：

```c
uint8_t SPI_ReadRegister(uint8_t reg)
{
  uint8_t tx_data[2] = {
    (uint8_t)(reg | 0x80U),
    0xFFU
  };
  uint8_t rx_data[2] = {0};

  HAL_GPIO_WritePin(SPI_CS_GPIO_Port,
                    SPI_CS_Pin,
                    GPIO_PIN_RESET);

  HAL_StatusTypeDef status = HAL_SPI_TransmitReceive(
      &hspi1,
      tx_data,
      rx_data,
      2U,
      100U);

  HAL_GPIO_WritePin(SPI_CS_GPIO_Port,
                    SPI_CS_Pin,
                    GPIO_PIN_SET);

  if (status != HAL_OK) {
    return 0U;
  }

  return rx_data[1];
}
```

中断或DMA模式下，CS通常在启动传输前拉低，在发送接收完成回调中拉高。若多个任务或中断共用同一SPI接口，还需要增加互斥和总线所有权管理。

## Arduino示例
Arduino使用SPI库时，应把每个外设的配置放入`SPISettings`，并使用事务接口保护总线配置：

```cpp
#include <SPI.h>

const uint8_t chipSelect = 10;
SPISettings deviceSettings(1000000UL,
                           MSBFIRST,
                           SPI_MODE0);

void setup()
{
  pinMode(chipSelect, OUTPUT);
  digitalWrite(chipSelect, HIGH);
  SPI.begin();
}

uint8_t readRegister(uint8_t reg)
{
  SPI.beginTransaction(deviceSettings);
  digitalWrite(chipSelect, LOW);

  SPI.transfer(reg | 0x80U);
  uint8_t value = SPI.transfer(0xFFU);

  digitalWrite(chipSelect, HIGH);
  SPI.endTransaction();
  return value;
}
```

不同Arduino开发板的SPI引脚位置可能不同，应根据板级引脚图使用默认SPI引脚或指定的SPI实例。相关函数可参考[[Arduino常用函数]]。

## SPI与I2C、UART的区别
| 特性 | SPI | [[I2C通信]] | [[串口通信]] |
| --- | --- | --- | --- |
| 时钟 | 控制器提供SCK | 控制器提供SCL | 通常没有独立时钟线 |
| 常见数据线 | SCK、COPI、CIPO、CS | SCL、SDA | TX、RX |
| 传输方向 | 通常全双工 | 半双工 | 全双工 |
| 多设备选择 | 每个外设常用独立CS | 使用总线地址 | 通常点对点 |
| 硬件应答 | 没有统一应答机制 | 有ACK/NACK | 没有统一应答机制 |
| 常见优势 | 速度高、时序直接 | 连线少、便于挂接多个器件 | 简单、适合设备间或调试通信 |
| 常见限制 | 占用引脚较多、协议不统一 | 上拉和总线电容限制速度 | 双方需要预先约定波特率 |

## 相关扩展接口
- Dual SPI：使用两根双向数据线并行传输
- Quad SPI/QSPI：使用四根数据线，常用于外部Flash
- OctoSPI：使用八根数据线，可进一步提高外部存储器带宽
- Microwire：与SPI相似的同步串行接口，但帧格式和控制方式有所不同

这些接口增加数据线数量以提升吞吐量，通常在命令、地址和数据阶段使用不同的线路宽度，并不等同于标准四线SPI的全双工传输。

## 常见问题排查
### 始终读到`0xFF`
- 外设未被选中，CS没有正确拉低
- CIPO悬空、断线或被上拉
- 外设没有供电，或没有共地
- 命令、地址或Dummy Byte数量不正确
- 外设仍处于复位、休眠或掉电状态

### 始终读到`0x00`
- CIPO被短接到地或被其他器件持续拉低
- 读取阶段没有继续产生时钟
- 外设返回数据前还需要额外Dummy Byte
- 片选过早释放

### 数据整体移位或数值固定错误
- CPOL或CPHA设置错误
- MSB First与LSB First设置错误
- 数据长度设置错误，如一端8位、另一端16位
- CS到第一个时钟边沿的建立时间不足

### 低速正常，高速出错
- 超过外设允许的最高SCK频率
- 走线或杜邦线过长，信号反射和串扰加重
- 电平转换器速度不足
- GPIO驱动速度、负载电容或返回数据延迟造成时序裕量不足
- 电源去耦不足，通信时产生电源波动

### 只在第一次通信时正常
- 上一次事务后CS没有恢复无效状态
- 没有等待Busy标志清零就释放CS或重新配置SPI
- 接收缓冲区溢出标志没有按控制器规定清除
- 外设内部状态机需要停止条件、复位命令或额外时钟

### 多个外设单独工作正常，接到一起后异常
- 多个CS同时有效
- 未选中的外设没有释放CIPO
- 切换外设时没有更新SPI模式或频率
- 某个外设在上电期间通过保护二极管反向供电并影响总线

使用逻辑分析仪时，应同时观察CS、SCK、COPI和CIPO，并按照外设要求设置解码器的模式、位序和每帧位数。先核对片选范围，再检查命令、地址、Dummy Byte和返回数据，比只观察解码出的十六进制值更可靠。
