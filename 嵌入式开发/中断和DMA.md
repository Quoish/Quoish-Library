# 中断和DMA
中断（Interrupt）和DMA（Direct Memory Access，直接存储器访问）都是减少CPU等待时间的重要机制。

- 中断用于通知CPU“某个事件已经发生”，CPU暂停当前任务并执行对应的处理程序
- DMA用于在外设和存储器之间批量搬运数据，传输过程主要由DMA控制器完成
- DMA通常仍会在传输过半、传输完成或发生错误时通过中断通知CPU

轮询、中断和DMA的主要区别在于CPU参与工作的频率：轮询需要CPU不断检查状态；中断只在事件发生时调用CPU；DMA把高频的数据搬运交给硬件，CPU只负责配置和处理成块的数据。

# 中断
## 中断的基本结构
一次完整的中断通常涉及以下部分：

- 中断源（Interrupt Source）：产生事件的外设或处理器部件，如GPIO边沿、定时器溢出、串口接收和ADC转换完成
- 状态标志（Flag）：记录某个事件已经发生
- 中断使能（Interrupt Enable）：决定该事件是否能够向中断控制器发送请求
- 中断控制器：接收多个中断请求，按照屏蔽状态和优先级选择需要响应的中断
- 中断向量表（Vector Table）：保存各个中断服务程序的入口地址
- 中断服务程序（ISR，Interrupt Service Routine）：中断发生后实际执行的函数

外设状态标志与中断请求是两个相关但不同的概念。即使没有启用中断，外设仍可能设置状态标志，主程序可以通过轮询读取该标志；只有同时满足中断使能和中断控制器允许响应等条件时，CPU才会进入ISR。

## 中断的执行过程
1. 外设检测到事件，设置对应的状态标志
2. 若该事件的中断已使能，外设向中断控制器发出请求
3. 中断控制器将请求置为挂起（Pending），并与当前任务及其他中断比较优先级
4. CPU完成当前不能被中断的操作后，保存必要的运行现场
5. CPU从中断向量表取得ISR入口地址，开始执行中断服务程序
6. ISR读取事件来源、处理必要数据并清除相应标志
7. 执行中断返回，CPU恢复现场并继续原来的任务

在Cortex-M处理器中，进入异常时硬件会自动保存一部分核心寄存器，并通过向量表跳转到处理函数；执行异常返回时再恢复这些寄存器。不同处理器保存现场的方式和具体寄存器可能不同。

## 中断的状态
一个中断常见的状态包括：

- Inactive：没有挂起，也没有正在执行
- Pending：中断请求已经产生，正在等待CPU响应
- Active：CPU正在执行该中断的ISR
- Active and Pending：ISR执行期间同一中断再次发生，当前中断处于活动状态，同时又有新的请求等待处理

外设标志和中断控制器的Pending状态不一定同时清除。处理一个中断时，需要根据芯片手册确认应该清除外设标志、中断控制器挂起位，还是由读取寄存器等特定操作完成清除。

## 中断向量表
中断向量表保存复位入口、处理器异常和外设中断的处理函数地址。程序启动时，CPU从向量表找到相应入口。

在许多开发框架中，启动文件会为各个中断提供默认的弱定义处理函数。用户使用规定名称重新定义处理函数后，链接器会用用户实现覆盖默认实现。

以Cortex-M为例，处理器异常通常包括Reset、NMI、HardFault、SysTick等；GPIO、串口、定时器和DMA等属于芯片厂商定义的外设中断。具体中断编号和向量表排列应查阅对应芯片的数据手册或启动文件。

## 中断优先级和嵌套
当多个中断同时发生时，中断控制器根据优先级决定响应顺序。若处理器支持中断嵌套，高优先级中断还可以暂停低优先级ISR并立即执行。

在Cortex-M系统中，优先级数值越小通常表示优先级越高。芯片实际实现的优先级位数由具体型号决定，因此可用的优先级数量也不同。

以STM32使用的NVIC配置为例，优先级可以分为：

- 抢占优先级（Preemption Priority）：决定一个中断能否打断另一个正在执行的中断
- 子优先级（Subpriority）：当多个具有相同抢占优先级的中断同时处于Pending状态时，决定先响应哪一个

具有相同抢占优先级的中断不能互相抢占。子优先级只决定等待中的响应顺序，不会使一个ISR打断另一个ISR。

优先级设置的一般原则：

1. 对响应时间要求最高的中断设置较高优先级，如安全保护、紧急停机和严格时序采样
2. 高频中断的ISR应尽量短，避免长期占用CPU
3. 会被多个中断访问的资源需要考虑竞争和数据一致性
4. 不应把大量普通业务都设置为最高优先级，否则优先级机制会失去作用

## 外部中断
外部中断用于检测芯片引脚上的电平或边沿变化，常见触发方式包括：

- 上升沿触发：信号从低电平变为高电平
- 下降沿触发：信号从高电平变为低电平
- 双边沿触发：上升沿和下降沿都能触发
- 电平触发：信号保持在指定电平时持续满足触发条件，是否支持取决于芯片

GPIO外部中断通常需要经过引脚复用或外部中断控制器，再连接到处理器的中断控制器。在STM32中，这部分通常由EXTI和NVIC共同完成，部分EXTI线还会共享同一个中断入口，因此ISR中需要检查具体是哪一条线产生了请求。

机械按键会产生抖动，一次按下可能触发多个边沿。可以使用硬件滤波、定时器延时确认或状态机进行消抖，不宜在ISR中直接执行较长时间的阻塞延时。

## 中断服务程序的编写原则
- ISR只完成读取数据、清除标志和记录事件等必要工作
- 耗时计算、字符串输出、文件操作和复杂协议解析应放到主循环或任务中执行
- 避免在ISR中使用无法确定等待时间的阻塞函数
- ISR与主程序共享的简单状态变量通常需要使用`volatile`，防止编译器把实际需要重复读取的变量长期保存在寄存器中
- `volatile`不能保证复合操作的原子性，也不能自动解决多个执行上下文之间的竞争
- 多字节数据、读改写操作或多个相关变量需要使用临界区、原子操作、消息队列等同步方式保护
- 清除中断标志时应遵循芯片手册规定。有些标志写1清零，有些标志需要按顺序读取寄存器，还有些标志由硬件自动清除

常用的处理方式是让ISR只设置事件标志：

```c
static volatile bool data_ready = false;

void peripheral_irq_handler(void)
{
    clear_interrupt_flag();
    data_ready = true;
}

int main(void)
{
    while (1)
    {
        if (data_ready)
        {
            data_ready = false;
            process_data();
        }
    }
}
```

若事件发生速度可能快于主程序处理速度，单个布尔标志无法表示累计发生次数，此时应使用计数器、环形缓冲区或消息队列。

## STM32 HAL中的中断调用关系
使用STM32 HAL时，一次外设中断通常经过以下过程：

1. 外设产生中断请求
2. CPU进入启动文件中规定的`xxx_IRQHandler`
3. `xxx_IRQHandler`调用对应的`HAL_xxx_IRQHandler`
4. HAL检查并清除标志，然后调用相应的回调函数
5. 用户在`HAL_xxx_Callback`中编写应用层处理逻辑

例如串口接收、定时器溢出和ADC转换完成分别可能进入`HAL_UART_RxCpltCallback`、`HAL_TIM_PeriodElapsedCallback`和`HAL_ADC_ConvCpltCallback`。具体函数见[[HAL库常用函数]]。

# DMA
## DMA的基本原理
DMA控制器能够在存储器和外设之间传输数据。CPU先配置源地址、目标地址、传输数量和工作模式，之后每次外设产生DMA请求时，DMA控制器取得总线控制权并完成一次或一组传输。

DMA常见的传输方向包括：

- 外设到存储器（Peripheral to Memory）：如串口接收、ADC采样
- 存储器到外设（Memory to Peripheral）：如串口发送、DAC输出
- 存储器到存储器（Memory to Memory）：用于数据块复制，是否支持取决于DMA控制器

DMA减少了CPU逐字节或逐采样点搬运数据的工作量，但DMA和CPU仍可能竞争存储器总线。高速、连续或高优先级DMA传输可能增加CPU访问存储器的等待时间。

## DMA的组成
- DMA请求源：发出传输请求的外设事件，如串口接收数据寄存器非空、ADC转换完成
- 通道或数据流（Channel/Stream）：执行传输的硬件资源，不同芯片的命名和组织方式不同
- 源地址：数据读取位置
- 目标地址：数据写入位置
- 传输计数器：记录剩余的数据单元数量
- 地址递增：每次传输后是否自动增加源地址或目标地址
- 数据宽度：一次传输的数据大小，常见为8位、16位或32位
- 仲裁器：多个DMA请求同时出现时，根据优先级选择先服务的通道

部分芯片的DMA请求与通道固定映射，部分芯片可以通过请求复用器灵活选择。配置之前需要查阅芯片的DMA请求映射表。

## DMA的传输过程
1. 禁用准备配置的DMA通道，确认上一次传输已经停止
2. 清除上一次传输留下的完成、半传输和错误标志
3. 设置传输方向、源地址和目标地址
4. 设置数据宽度、地址递增方式和传输数量
5. 选择普通模式或循环模式，并配置通道优先级
6. 根据需要启用半传输、传输完成和传输错误中断
7. 启用DMA通道和对应外设的DMA请求
8. 外设产生请求后，DMA控制器自动搬运数据并更新地址和剩余数量
9. 达到指定传输量后，DMA设置完成标志，并可触发中断通知CPU

配置顺序会随芯片不同而变化。有些DMA寄存器只能在通道禁用时修改，重新启动前还需要清除旧标志并重新装载传输计数。

## DMA的关键配置
### 传输方向
源地址和目标地址必须与数据流向一致。例如串口接收时，源地址是串口数据寄存器，目标地址是内存缓冲区；串口发送时则相反。

### 地址递增
- 外设寄存器地址通常保持不变，因为每次都访问同一个数据寄存器
- 内存地址通常自动递增，使数据依次写入或读出数组
- 若要反复向同一地址写入，或从同一地址重复读取，也可以关闭相应地址的递增

### 数据宽度和对齐
外设宽度和内存宽度应与寄存器及缓冲区类型相匹配。例如8位串口数据通常使用字节宽度，12位ADC结果通常保存在16位数据中。

很多DMA控制器的传输数量表示“数据单元个数”，并不一定表示字节数。例如把数据宽度设为16位、数量设为100，通常表示传输100个半字，共200字节。

源地址和目标地址还应满足芯片的对齐要求。宽度或对齐配置错误可能导致数据错位、截断或总线错误。

### 通道优先级
DMA优先级决定多个通道同时请求时的仲裁顺序。高优先级适合不能及时暂停的数据流，如高速ADC采样或连续通信接收；低速、允许等待的数据传输可以设置较低优先级。

DMA优先级只影响DMA通道之间的仲裁，不等同于DMA完成中断在中断控制器中的优先级，这两种优先级需要分别配置。

## 普通模式和循环模式
### 普通模式
普通模式（Normal Mode）在完成指定数量的数据传输后停止，适合长度已知的一次性数据块，如发送一帧数据或采集固定数量的样本。

若要再次传输，需要重新设置地址、数量并启动DMA。传输期间使用的缓冲区必须一直有效，不能被提前释放或改作他用。

### 循环模式
循环模式（Circular Mode）在计数减到零后自动重新装载初始计数和地址，继续下一轮传输，适合ADC连续采样、音频流和持续串口接收。

循环DMA常配合半传输中断和传输完成中断使用：

1. DMA写满缓冲区前半段，触发半传输中断，CPU处理前半段
2. DMA继续写入后半段
3. DMA写满后半段，触发传输完成中断，CPU处理后半段
4. DMA回到缓冲区开头继续写入

这种方式也称为乒乓缓冲或双半缓冲。CPU处理某一半缓冲区时，DMA可以同时写入另一半。如果CPU处理速度低于DMA覆盖缓冲区的速度，尚未处理的数据仍会丢失。

部分DMA控制器提供真正的双缓冲模式，可以在两个独立地址之间自动切换；不支持双缓冲的控制器也可以利用循环模式和缓冲区的前后两半实现相似效果。

## DMA中断
DMA常见的中断事件包括：

- Half Transfer：已经完成一半数据传输
- Transfer Complete：指定数量的数据已经全部传输完成
- Transfer Error：传输过程中发生总线、地址或配置错误
- FIFO Error：带FIFO的DMA控制器发生FIFO上溢、下溢等错误，具体取决于芯片

DMA中断的ISR同样应尽量简短。常见做法是记录哪一段缓冲区已经就绪，再由主循环或操作系统任务完成数据解析。

DMA完成中断只说明DMA控制器已经完成配置的数据搬运。对于串口发送等操作，DMA把最后一个数据写入外设数据寄存器时，通信线路可能仍在发送最后一帧；若后续操作要求物理线路已经空闲，还需要检查外设自身的发送完成标志。

## DMA与缓存
带数据缓存（D-Cache）的处理器需要考虑缓存一致性：

- CPU写入发送缓冲区后，数据可能仍停留在缓存中，DMA读取到的内存内容可能还是旧数据
- DMA写入接收缓冲区后，CPU缓存中可能仍保留旧副本

启动DMA发送前可能需要清理（Clean）缓存，读取DMA接收结果前可能需要失效（Invalidate）缓存，并且缓冲区地址和长度通常要满足缓存行对齐要求。没有数据缓存的低端微控制器一般不需要这一步。

## 常见应用
### ADC连续采样
[[定时器]]按照固定频率产生触发信号，[[ADC]]每次完成转换后发出DMA请求，DMA把结果依次写入循环缓冲区。CPU只在半缓冲区或整个缓冲区完成时批量处理数据，可以得到稳定的采样间隔并显著减少中断次数。

### 串口接收
[[串口通信|串口]]每收到一个数据就产生DMA请求，DMA把数据寄存器的内容写入接收缓冲区。对于固定长度的数据，可以等待传输完成；对于不定长数据，可以结合串口空闲事件、协议帧头帧尾或循环缓冲区判断有效数据范围。

### 波形输出
DMA可以把内存中的波形数据持续写入DAC、PWM比较寄存器或其他输出外设，实现周期波形输出。定时器负责确定更新频率，DMA负责提供下一份数据。

# 轮询、中断和DMA的选择
- 数据量很小、事件很快完成、程序结构简单时，可以使用轮询
- 事件发生频率较低或每次只需处理少量数据时，适合使用中断
- 数据连续到达、传输频率较高或需要批量搬运时，适合使用DMA
- DMA配置和缓冲区管理有额外复杂度，低频单字节操作不一定能从DMA中获益

常见的组合方式是“硬件触发外设，DMA搬运数据，中断通知CPU处理数据块”。这样可以把采样时刻和数据传输交给硬件，同时让CPU集中处理已经准备好的数据。

# 常见问题
1. 中断不断重复进入：通常是事件标志没有正确清除，或触发条件一直保持有效
2. 中断没有响应：检查外设事件使能、中断控制器使能、优先级屏蔽、向量表和处理函数名称
3. ISR执行时间过长：减少ISR中的计算和阻塞操作，把工作转移到主循环或任务
4. DMA没有启动：检查请求映射、传输方向、通道使能和外设DMA请求使能
5. DMA数据错位：检查数据宽度、地址对齐、地址递增和缓冲区类型
6. 循环DMA丢数据：增加缓冲区、提高数据处理速度，或降低数据产生速率
7. DMA缓冲区内容不更新：在带缓存的处理器上检查缓存维护操作
8. 共享数据偶尔异常：检查ISR、DMA和主程序是否同时访问同一缓冲区，并使用合适的同步机制
