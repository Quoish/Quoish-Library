# 核心图景：学习在当前文本后面，什么词元更可能出现

自回归语言模型反复执行同一种操作：读取已有前缀，输出下一个词元的概率分布，选出一个词元接到末尾，再继续。多个局部预测串起来，就形成完整回答。

这给出了可扩展的训练目标，也留下一个重要边界：高概率的续写不一定是事实正确、满足要求或有充分证据的回答。

# 问题域与发展背景

早期 n-gram 模型根据有限长度的上下文计数，面对罕见组合和更长依赖时容易稀疏。神经表示让不同上下文共享参数，RNN 通过状态处理序列，Transformer 又改善了位置交互和大规模训练的并行组织。

预训练路线进一步提出：先从大量通用文本获得可迁移能力，再适配具体任务，减少每个任务从零学习的成本。2020年的[GPT-3 工作](https://arxiv.org/abs/2005.14165)研究扩大规模后在提示内提供少量示例的任务表现。

但“会继续写文本”与“按人的指令提供合适帮助”并非相同训练要求。2022年的[InstructGPT 工作](https://arxiv.org/abs/2203.02155)通过监督示范和人类反馈等步骤调整模型行为。这条发展线承接的是目标差异问题，不能理解为只扩大参数量就自动完成指令对齐。

# 概率分解怎样变成训练任务

把一段文本分成词元$x_1,\ldots,x_T$。链式法则给出

$$
P(x_1,\ldots,x_T)=\prod_{t=1}^TP(x_t\mid x_{<t}).
$$

$x_{<t}$是位置$t$之前的前缀。模型分别估计每个条件分布；某个给定序列的概率就是沿路径各条件概率相乘。例如三个条件概率为0.5、0.8、0.25，乘积为0.1。

训练最大化真实序列概率，通常改写成最小化平均负对数似然：

$$
L=-\frac1M\sum_{t\in\mathcal I}\log P_\theta(x_t\mid x_{<t}).
$$

$\mathcal I$是实际参与损失的位置，$M$为其数量；填充或某些提示位置可不计入目标。取负对数把乘积变成和，也把“提高正确词元概率”变成可以反向传播的损失。

# 为什么输入和标签要错开一位

以字符级句子“春天开花。”为例，输入可以是$[\text{春},\text{天},\text{开},\text{花}]$，目标是$[\text{天},\text{开},\text{花},\text{。}]$。

| 可见前缀 | 本位置要预测的下一个字符 |
|---|---|
| 春 | 天 |
| 春天 | 开 |
| 春天开 | 花 |
| 春天开花 | 。 |

训练时参考答案已知，可以并行计算这些位置，但因果掩码禁止当前位置看到未来目标。下方微型例程按字符建立词表；真实 Qwen 入口使用模型配套 tokenizer，词元未必是单个汉字。

# 预训练、指令微调与偏好对齐

| 阶段 | 主要数据与信号 | 希望改善什么 |
|---|---|---|
| 预训练 | 大量文本中的预测目标 | 通用语言与知识关联、可迁移表示 |
| 指令微调 | 问题、指令、示范回答 | 按任务和对话格式作答 |
| 偏好对齐 | 回答比较、奖励或偏好标签 | 让输出更符合特定评价偏好 |

对话微调常只在助手回答部分计算损失。RLHF 和直接偏好优化属于不同实现路线，不能只根据“有人类反馈”便认为算法相同。

这些阶段都受数据质量与目标约束。低训练损失可能来自记忆，偏好得分高也不等同于所有事实都准确。大型语言模型的能力还与规模和训练经验有关，微型教学模型只复现基本机制。

# 一次生成具体怎样执行

1. 用聊天模板组织角色与已有内容。
2. tokenizer 转换为编号，模型输出最后位置的词表 logits。
3. 根据策略选出下一个词元。
4. 接到前缀末尾，重复，直至结束标记或长度上限。

贪心策略每次取最大概率。它不保证整个序列最优：若首词A概率0.6、B概率0.4，之后A分支最好续词概率0.5、B分支为0.99，则两条最佳路径分别为0.3和0.396，逐步贪心仍会先选A。

# 温度、Top-k 与 Top-p

温度采样将 logits 除以$T>0$后再归一化：

$$
p_i(T)=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}.
$$

若分数为$[2,1,0]$：温度1时概率约$[0.665,0.245,0.090]$；温度2时约$[0.506,0.307,0.186]$；温度0.5时约$[0.867,0.117,0.016]$。低温度让分布更尖，高温度增加抽到低分词的机会。

Top-k 只保留最高的$k$个候选，Top-p 保留累计概率达到指定阈值的一组高分候选，再重新归一化采样。它们改变多样性与重复倾向，不能独立保证回答正确。

本例预训练入口采用贪心生成，不启用随机采样，便于重复核对；这也不代表同一输出在所有任务里更优。

# 推理时的资源概念

**上下文窗口**限制一次能处理的词元位置，预算包含提示、历史与生成。**KV cache**复用已计算的各层历史键值，减少逐步生成的重复计算，同时占用内存。**量化**减少权重等对象的表示精度，可能降低资源需求，也可能影响效果或速度。

这些概念分别涉及长度、重复计算和数值表示，与更新权重的训练步骤不能混为一谈。外部检索知识库则属于[[检索增强生成]]讨论的系统层。

# 评价与复习线索

困惑度$\mathrm{PPL}=\exp(L)$把平均负对数似然转换成另一种尺度。若$L=\log4$，困惑度为4；它依赖语料、分词器和损失统计方式，不能无条件跨模型比较。

具体应用还要评价指令遵循、事实性、引用、稳定性和成本。看到流畅文本时，应继续问训练目标与当前任务的要求是否一致，以及是否有独立证据支持答案。

下方 `train.py` 仅学习重复的四季句式，低损失和复现句子不能证明通用语言能力；`pretrained.py` 则展示完整的本地模型、tokenizer、聊天模板与生成链。

```python
"""统一处理项目路径、随机种子、CPU线程与计算设备。"""

# 标准库
from pathlib import Path
import argparse
import random

# 第三方库（由统一环境提供）
import numpy as np
import torch

# 1. 路径统一从 runtime.py 所在目录出发，复制项目后无须改绝对路径。
ROOT = Path(__file__).resolve().parent

# outputs/ 存放本项目的图像、指标与模型权重；不存在时自动创建。
OUT = ROOT / "outputs"
OUT.mkdir(exist_ok=True)


def setup():
    """初始化运行环境并返回 torch.device。

    命令行参数只有 --cpu；ROOT、OUT 是导入时建立的项目路径。
    """

    # 2. 读取命令行选项：--cpu 允许在有显卡的机器上仍强制使用 CPU。
    parser = argparse.ArgumentParser()
    parser.add_argument("--cpu", action="store_true")
    args = parser.parse_args()

    # 3. 固定 Python、NumPy 和 PyTorch 的随机种子；跨设备仍不保证逐位相同。
    random.seed(7)
    np.random.seed(7)
    torch.manual_seed(7)

    # 小型教学网络限制 CPU 线程数，避免线程调度开销过大。
    torch.set_num_threads(2)

    # 4. 仅当 CUDA 可用且没有指定 --cpu 时使用 GPU；调用方负责移动模型和数据。
    device = torch.device(
        "cuda" if torch.cuda.is_available() and not args.cpu else "cpu"
    )
    print("device:", device)

    # 返回 torch.device；各入口脚本共用相同的设备选择规则。
    return device
```

### `model.py`

```python
"""定义用于字符级下一词元预测的两层因果 Transformer。"""

# 第三方库（由统一环境提供）
import torch
from torch import nn


class CharLM(nn.Module):
    """定义用于字符级下一词元预测的两层因果 Transformer。"""

    def __init__(self, vocab, context=32):
        """vocab 为字符表大小；context 为可处理的最大窗口长度，默认32。"""

        super().__init__()

        # 1. 字符编号查表为48维表示，再加上学习式位置向量。
        self.token = nn.Embedding(vocab, 48)
        self.position = nn.Embedding(context, 48)

        # 2. 每层使用4头注意力、96维前馈中间层和 Pre-LN；dropout=0 便于复核。
        block = nn.TransformerEncoderLayer(
            48, 4, dim_feedforward=96, dropout=0, batch_first=True, norm_first=True
        )

        # 堆叠两层；关闭嵌套张量路径，使用清楚的定长批量输入。
        self.blocks = nn.TransformerEncoder(block, 2, enable_nested_tensor=False)

        # 3. 在词表投影前归一化，输出每个字符位置的词表分数。
        self.norm = nn.LayerNorm(48)
        self.head = nn.Linear(48, vocab)

    def forward(self, ids):
        """将一批字符编号转换为因果下一字符 logits；不在这里进行采样。"""

        # 输入为 (B, T)；T 不得超过 context 所定义的位置表长度。
        t = ids.shape[1]
        x = self.token(ids) + self.position(torch.arange(t, device=ids.device))

        # 虽然使用 TransformerEncoder 组件，但显式因果掩码使每个位置只读当前及过去。
        mask = torch.ones(t, t, dtype=torch.bool, device=ids.device).triu(1)

        # 输出 (B, T, vocab)；训练函数负责构造移位标签和交叉熵。
        return self.head(self.norm(self.blocks(x, mask=mask)))
```

### `train.py`

```python
"""从零训练小型字符语言模型，再用贪心策略逐字符生成。"""

# 标准库
import json

# 第三方库（由统一环境提供）
import torch
from torch import nn

# 本项目模块
from runtime import setup, OUT
from model import CharLM


def main():
    """从零训练小型字符语言模型，再用贪心策略逐字符生成。

    按分段注释依次准备数据、执行计算并保存结果。
    """

    # 1. 初始化设备；这个入口使用内置重复文本，不下载大模型。
    device = setup()

    # 2. 训练语料只有固定四季句式，主要演示记忆和生成流程，不评价通用语言能力。
    text = "春天开花。夏天听雨。秋天落叶。冬天看雪。\n" * 40

    # 建立稳定的字符表与字符编号映射；本例直接按字符分词。
    chars = sorted(set(text))
    stoi = {c: i for i, c in enumerate(chars)}

    # 将全文编码成一维整数张量，之后随机裁剪连续训练窗口。
    data = torch.tensor([stoi[c] for c in text], device=device)

    # 3. 创建字符模型与优化器；词表大小由当前语料决定。
    model = CharLM(len(chars)).to(device)
    optimizer = torch.optim.Adam(model.parameters(), lr=0.003)
    initial = None

    # 4. 每一步抽取16个长度24的输入窗口，目标整体向后移一个字符。
    for step in range(250):
        # 起点需为后续25个字符留足空间，避免移位目标越过文本结尾。
        starts = torch.randint(0, len(data) - 25, (16,), device=device)

        # 广播生成 (16, 24) 的位置矩阵；同一个窗口内保持原始字符顺序。
        indices = starts[:, None] + torch.arange(24, device=device)
        x, y = data[indices], data[indices + 1]

        # 清除上一轮梯度；PyTorch 的 backward 默认会累加到 .grad。
        optimizer.zero_grad()

        # 模型输出 (16, 24, 词表大小)，随后将批次与时间维合并计算交叉熵。
        logits = model(x)

        # 构造当前批次的标量训练目标，反向传播将从这里开始。
        loss = nn.functional.cross_entropy(
            logits.reshape(-1, len(chars)), y.reshape(-1)
        )

        # 记录初始损失以对照学习是否发生；每轮损失仍来自当前随机窗口。
        if initial is None:
            initial = loss.item()

        # 沿计算图计算参数梯度；此时参数数值尚未更新。
        loss.backward()

        # 限制全部参数梯度的总范数，缓解梯度爆炸；不改变前向预测。
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1)

        # 优化器根据当前梯度真正更新可训练参数。
        optimizer.step()

    # 切换到评价模式；若含 Dropout／BatchNorm，其行为随之切换。
    model.eval()

    # 5. 以“春”作为生成前缀，逐次追加一个预测字符。
    generated = torch.tensor([[stoi["春"]]], device=device)

    # 不记录这一段的求导图；适用于评价、参数初始化或手动更新。
    with torch.no_grad():
        for _ in range(60):
            # 只保留最近32个字符，取最后一个位置的最大 logit 作为下一个字符编号。
            next_id = model(generated[:, -32:])[:, -1].argmax(-1, keepdim=True)

            # 5. 以“春”作为生成前缀，逐次追加一个预测字符。

            # 把新编号接到序列末尾；下一轮模型会把它当成已知输入。
            generated = torch.cat([generated, next_id], dim=1)

    # 6. 将整数编号解码回文本，并保存损失、示例和包含词表的检查点。
    sample = "".join(chars[i] for i in generated[0].tolist())
    print("initial loss:", initial, "final loss:", loss.item())
    print(sample)
    (OUT / "sample.txt").write_text(sample, encoding="utf-8")
    (OUT / "metrics.json").write_text(
        json.dumps(
            {
                "initial_loss": initial,
                "final_loss": loss.item(),
            },
            indent=2,
        ),
        encoding="utf-8",
    )
    torch.save(
        {
            "state": model.state_dict(),
            "chars": chars,
        },
        OUT / "char_lm.pt",
    )


if __name__ == "__main__":
    main()
```

### `pretrained.py`

```python
"""使用本地 Qwen 指令模型和其配套聊天模板生成一段中文回答。"""

# 第三方库（由统一环境提供）
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

# 本项目模块
from runtime import setup, OUT


def main():
    """使用本地 Qwen 指令模型和其配套聊天模板生成一段中文回答。

    按分段注释依次准备数据、执行计算并保存结果。
    """

    # 1. 选择设备；首次运行下载模型和 tokenizer，后续复用缓存。
    device = setup()

    # 2. tokenizer 必须与模型权重配套，不能任意替换词表或词元编号。
    model_id = "Qwen/Qwen2.5-0.5B-Instruct"
    tokenizer = AutoTokenizer.from_pretrained(model_id)

    # CUDA 使用 float16 降低显存占用；CPU 使用 float32 以保持兼容性。
    dtype = torch.float16 if device.type == "cuda" else torch.float32

    # 加载 safetensors 权重，并使用统一环境支持的普通注意力实现。
    model = (
        AutoModelForCausalLM.from_pretrained(
            model_id,
            torch_dtype=dtype,
            use_safetensors=True,
            attn_implementation="eager",
        )
        .to(device)
        .eval()
    )

    # 3. 用角色列表表示对话；system 给出行为要求，user 给出本次问题。
    messages = [
        {
            "role": "system",
            "content": "你是一位简明的中文教学助手。",
        },
        {
            "role": "user",
            "content": "用两句话解释什么是神经网络中的权重。",
        },
    ]

    # 按模型原有聊天模板插入角色和结束标记，并添加等待助手生成的提示。
    text = tokenizer.apply_chat_template(
        messages, tokenize=False, add_generation_prompt=True
    )

    # 4. 分词为整数张量及注意力掩码，整体移动到模型所在设备。
    inputs = tokenizer(text, return_tensors="pt").to(device)

    # 仅执行推理，不建立用于反向传播的计算图。
    with torch.inference_mode():
        # 5. 采用确定性的贪心生成，最多追加96个 token；不再设置采样温度。
        ids = model.generate(
            **inputs,
            max_new_tokens=96,
            do_sample=False,
            temperature=None,
            top_p=None,
            top_k=None,
            pad_token_id=tokenizer.eos_token_id,
        )

    # 6. generate 返回“输入前缀＋新生成内容”；切掉前缀后才是本次回答。
    answer = tokenizer.decode(
        ids[0, inputs.input_ids.shape[1] :], skip_special_tokens=True
    )

    # 同时打印并保存实际回答，内容质量仍需对照问题检查。
    print(answer)
    (OUT / "pretrained_answer.txt").write_text(answer, encoding="utf-8")


if __name__ == "__main__":
    main()
```

## 结果与解释

微型训练的最终损失应显著低于初始值，生成通常复现四季句式。重复语料使记忆很容易，项目没有独立泛化测试，也不应把它解释为模型学会了常识。预训练入口输出实际中文回答，内容仍需核对；权重下载和 CPU 推理耗时取决于网络与硬件。
