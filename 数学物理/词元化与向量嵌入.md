# 核心图景：文本先变成编号，编号再查表得到向量

模型不能直接对汉字的字形或字符串名称求梯度。常见入口是：**文本 → 词元序列 → 整数编号 → 嵌入向量 → 上下文网络**。

其中编号只是索引。编号100与101并不天然比100与900在语义上更接近；有用的距离来自经过训练的向量表示。

# 问题域与技术发展

把每个词当作完全孤立的符号，会让罕见组合很难与已有经验共享信息。神经概率语言模型通过连续表示学习相似性，[Bengio 等，2003](https://www.jmlr.org/papers/v3/bengio03a.html)是这一方向的重要工作。

2013年的[Word2Vec](https://arxiv.org/abs/1301.3781)强调以较高效率从上下文训练词表示。但静态表给同一词元同一个向量，难以区分它在不同语境中的用法。[BERT，2018](https://arxiv.org/abs/1810.04805)等上下文模型进一步让后续表示依赖整段输入。

句子检索又提出新的问题：若每一对句子都要共同送进网络打分，文档多时计算量很大。[Sentence-BERT，2019](https://arxiv.org/abs/1908.10084)等方法训练可分别编码的句向量，使文档表示能预先计算，再用向量相似度查找。

这条脉络同时包含几个不同层次：符号如何切开、单个词元如何查表、上下文如何改变表示，以及整段文本如何形成检索向量。

# 分词与词元编号

词元可以是完整词、子词、单字或字节片段。子词方法在词表规模、罕见表达和序列长度之间折中：常见片段可以整体保留，少见词则拆成已知小片段。

| 步骤 | 一个示意 | 需要记住的边界 |
|---|---|---|
| 分词 | “机器学习”变成若干片段 | 具体拆法由 tokenizer 决定 |
| 编号 | 片段映射为整数列表 | 数值大小不表达语义远近 |
| 查表 | 每个编号取一个向量 | 词表顺序必须与权重匹配 |

一个汉字、一个自然语言单词和一个 token 没有固定换算关系。预训练模型必须搭配其 tokenizer，否则同一个编号可能取到错误的含义入口。

# 从 one-hot 到可训练嵌入表

词表有$V$项时，第$i$项可用$V$维 one-hot 列向量$e_i$表示，只有第$i$项为1。它清楚表达身份，但不同词的 one-hot 都互相正交，无法自动体现语义关系。

设嵌入表$E\in\mathbb R^{V\times d}$，每行是一个$d$维向量，则

$$
v_i=E^Te_i.
$$

这相当于挑选第$i$行。实现中直接索引即可，无须真的建立巨大 one-hot。输入编号张量为$(B,T)$时，查表后得到$(B,T,d)$。

`nn.Embedding` 初始只是一张随机表。向量之所以有用，要由训练目标解释：如果某个向量有助于降低预测损失，梯度就会相应调整它。

# Skip-gram 怎样给词向量训练信号

以已分词句子“猫 喜欢 鱼”为例，窗口取相邻一个位置，可以得到“猫→喜欢”“喜欢→猫”“喜欢→鱼”“鱼→喜欢”等训练对。中心词是输入，上下文词是要预测的目标。

对中心$c$，查表得到$v_c$；再对每个候选上下文$o$计算分数，完整 Softmax 为

$$
P(o\mid c)=\frac{\exp(u_o^Tv_c)}{\sum_{j=1}^V\exp(u_j^Tv_c)},\quad
L=-\sum_{(c,o)}\log P(o\mid c).
$$

输入表示$v$和输出表示$u$通常是两组参数。模型不断提高实际上下文的相对分数。若两个词经常参与相似的上下文预测，它们可能学到某种相似结构；语料、窗口和任务目标都会改变这种结构。

CBOW 反过来由上下文预测中心词。大词表的完整 Softmax 很昂贵，负采样改用正词对与抽取的负词对构造对比目标，降低每步成本；它不是对完整归一化概率的逐项精确计算。

下方小项目采用完整 Softmax 的简化形式，训练语料有限，不能要求其近邻关系达到大型语料模型的水平。

# 上下文表示为什么又需要一层模型

“苹果上市”和“苹果很甜”中的词语需要结合周围内容解释。静态嵌入表对同一编号仍取同一行，但 RNN、Transformer 等后续网络会让它与其他位置交互，从而产生不同的上下文表示。

因此，**输入嵌入向量、某层隐藏状态和整句向量，并不是同一个对象**。模型中间表示可以携带很丰富的信息，却不一定适合直接用余弦做检索。

句向量常用池化将多位置表示变成固定长度向量，并通过专门的对比或检索目标训练。任意地平均一个语言模型的隐藏状态，不保证得到高质量语义搜索向量。

# 向量相似度怎样读

余弦比较方向：

$$
\cos(a,b)=\frac{a^Tb}{\|a\|\|b\|}.
$$

若两个向量已经单位化，分母就是1，矩阵乘法可以直接计算相似度。单位向量还满足$\|a-b\|^2=2-2a^Tb$，因此内积排序与欧氏距离排序对应。

人为取$a=(1,0)^T$、$b=(0.8,0.2)^T$，余弦约0.970；与$(0,1)^T$则为0。这个算例只演示几何意义，实际语义位置必须从训练中学到。

相似度高常表示在该模型目标下接近，不等于事实相同、逻辑等价或回答一定正确。否定句、数字、专有名词与任务差异，都可能让检索出错。

# 将本章接到注意力与 RAG

注意力会在每个位置的表示之间作匹配和汇总；RAG 则通常把文档片段压成可检索的向量，再将相关原文提供给生成器。两者都使用向量，但索引粒度、目标与后续计算不同。

下方 `main.py` 展示“词表与训练目标怎样共同塑造向量”，`semantic.py` 展示“预训练句向量怎样支持文档排序”。回顾时先确认正在讨论哪一类表示，再看向量维度与相似度。

# 可复原例程

项目包含两个入口：`main.py` 在小型已分词中文语料上训练 Skip-gram；`semantic.py` 下载中文嵌入模型进行句子检索。前者离线，后者首次联网下载模型。

### `runtime.py`

```python
"""统一处理项目路径、随机种子、CPU线程与计算设备。"""

# 标准库
from pathlib import Path
import argparse
import random

# 第三方库（由统一环境提供）
import numpy as np
import torch

# 1. 路径统一从 runtime.py 所在目录出发，复制项目后无须改绝对路径。
ROOT = Path(__file__).resolve().parent

# outputs/ 存放本项目的图像、指标与模型权重；不存在时自动创建。
OUT = ROOT / "outputs"
OUT.mkdir(exist_ok=True)


def setup():
    """初始化运行环境并返回 torch.device。

    命令行参数只有 --cpu；ROOT、OUT 是导入时建立的项目路径。
    """

    # 2. 读取命令行选项：--cpu 允许在有显卡的机器上仍强制使用 CPU。
    parser = argparse.ArgumentParser()
    parser.add_argument("--cpu", action="store_true")
    args = parser.parse_args()

    # 3. 固定 Python、NumPy 和 PyTorch 的随机种子；跨设备仍不保证逐位相同。
    random.seed(7)
    np.random.seed(7)
    torch.manual_seed(7)

    # 小型教学网络限制 CPU 线程数，避免线程调度开销过大。
    torch.set_num_threads(2)

    # 4. 仅当 CUDA 可用且没有指定 --cpu 时使用 GPU；调用方负责移动模型和数据。
    device = torch.device(
        "cuda" if torch.cuda.is_available() and not args.cpu else "cpu"
    )
    print("device:", device)

    # 返回 torch.device；各入口脚本共用相同的设备选择规则。
    return device
```

### `main.py`

```python
"""在已分词的小语料上训练完整 Softmax 的 Skip-gram 词向量。"""

# 标准库
import json

# 第三方库（由统一环境提供）
import torch
from torch import nn

# 本项目模块
from runtime import setup, OUT


def main():
    """在已分词的小语料上训练完整 Softmax 的 Skip-gram 词向量。

    按分段注释依次准备数据、执行计算并保存结果。
    """

    # 1. 初始化随机状态与设备；本入口只用内置语料，不下载预训练权重。
    device = setup()

    # 2. 空格在这里就是分词边界；没有额外调用中文分词器。
    sentences = [
        "猫 喜欢 鱼",
        "小猫 喜欢 鱼",
        "狗 喜欢 骨头",
        "小狗 喜欢 骨头",
        "猫 是 动物",
        "狗 是 动物",
        "小猫 是 动物",
        "小狗 是 动物",
        "苹果 是 水果",
        "香蕉 是 水果",
        "苹果 可以 食用",
        "香蕉 可以 食用",
    ]
    corpus = [s.split() for s in sentences]

    # 收集词表并排序，让同一语料的词元编号保持稳定。
    words = sorted({word for row in corpus for word in row})

    # 建立字符串到整数编号的映射，Embedding 接收编号而非原始文本。
    stoi = {word: i for i, word in enumerate(words)}

    # 3. 为每个中心词收集相邻一个位置的上下文，组成 (中心编号, 目标编号) 对。
    pairs = [
        (stoi[row[i]], stoi[row[j]])
        for row in corpus
        for i in range(len(row))
        for j in range(len(row))
        if i != j and abs(i - j) <= 1
    ]

    # 形状为 (词对数量, 2)；第0列查嵌入表，第1列是交叉熵目标。
    pairs = torch.tensor(pairs, device=device)

    # 4. 输入嵌入表形状 (词表大小, 12)，线性输出层把12维向量映射为词表 logits。
    embedding = nn.Embedding(len(words), 12).to(device)
    output = nn.Linear(12, len(words)).to(device)

    # 优化器同时训练嵌入表与输出层；仅建立随机嵌入表还没有语义结构。
    optimizer = torch.optim.Adam(
        list(embedding.parameters()) + list(output.parameters()), lr=0.03
    )

    # 5. 在所有词对上训练500次，目标是由中心词预测上下文。
    for step in range(500):
        # 清除上一轮梯度；PyTorch 的 backward 默认会累加到 .grad。
        optimizer.zero_grad()

        # 查表后得到 (词对数, 12)，再投影为 (词对数, 词表大小)。
        logits = output(embedding(pairs[:, 0]))

        # 构造当前批次的标量训练目标，反向传播将从这里开始。
        loss = nn.functional.cross_entropy(logits, pairs[:, 1])

        # 沿计算图计算参数梯度；此时参数数值尚未更新。
        loss.backward()

        # 优化器根据当前梯度真正更新可训练参数。
        optimizer.step()

    # 6. 训练后停止跟踪梯度，并将每个词向量单位化，使点积等于余弦相似度。
    vectors = nn.functional.normalize(embedding.weight.detach(), dim=1)
    query = stoi["猫"]

    # 与“猫”的向量比较全部词；排序时跳过该词自身，只展示其他近邻。
    similarity = vectors @ vectors[query]
    neighbors = [
        (words[i], float(similarity[i]))
        for i in similarity.argsort(descending=True)[1:6]
    ]
    print("loss:", loss.item(), "neighbors:", neighbors)

    # 7. 保存词表与未经单位化的嵌入权重；两者需要配套才能正确解释编号。
    torch.save(
        {
            "words": words,
            "embedding": embedding.weight.detach().cpu(),
        },
        OUT / "embedding.pt",
    )
    (OUT / "neighbors.json").write_text(
        json.dumps(neighbors, ensure_ascii=False, indent=2), encoding="utf-8"
    )


if __name__ == "__main__":
    main()
```

### `semantic.py`

```python
"""使用预训练 BGE 将句子编码为向量，演示小规模语义检索。"""

# 标准库
import json

# 第三方库（由统一环境提供）
from sentence_transformers import SentenceTransformer

# 本项目模块
from runtime import setup, OUT


def main():
    """使用预训练 BGE 将句子编码为向量，演示小规模语义检索。

    按分段注释依次准备数据、执行计算并保存结果。
    """

    # 1. 选择 CPU 或 CUDA；首次加载会下载公开模型，后续复用本地缓存。
    device = setup()

    # 2. 加载专门训练过的句向量模型，区别于另一入口中从零训练的小词表。
    model = SentenceTransformer("BAAI/bge-small-zh-v1.5", device=str(device))

    # 3. 候选库只有三个句子，便于人工核对检索结果。
    documents = ["猫喜欢吃鱼。", "苹果和香蕉属于水果。", "卷积神经网络可以处理图像。"]
    query = "小猫爱吃什么？"

    # 4. 每个句子得到一行向量；normalize_embeddings 让所有行的长度为1。
    vectors = model.encode(documents, normalize_embeddings=True)

    # 问题编码使用 BGE 的中文检索指令；文档本身不加同一前缀。
    q = model.encode(
        ["为这个句子生成表示以用于检索相关文章：" + query], normalize_embeddings=True
    )[0]

    # 5. 矩阵乘向量得到每个文档的余弦分数；分数不是答案正确概率。
    scores = vectors @ q

    # 将句子与分数配对后降序排列，保留文本以便检查是否真的相关。
    ranking = sorted(
        zip(documents, scores.tolist()), key=lambda item: item[1], reverse=True
    )

    # 6. 终端打印和 JSON 文件同时保存排序，不需要另建向量数据库。
    print(ranking)
    (OUT / "semantic.json").write_text(
        json.dumps(ranking, ensure_ascii=False, indent=2), encoding="utf-8"
    )


if __name__ == "__main__":
    main()
```

## 结果与解释

小语料 Skip-gram 的损失应下降，但邻居关系可能不稳定：语料极小，共享上下文也很有限。它展示可训练查表与预测目标，不足以验证语言语义。句向量项目应把关于猫吃鱼的句子排在前面；余弦分数不能直接解释为答案正确概率。
