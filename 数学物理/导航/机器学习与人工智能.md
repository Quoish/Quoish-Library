# 按问题理解技术发展

阅读技术史时，可以沿着四个问题追踪：**当时要解决什么任务？已有方法卡在哪里？新机制改变了哪一步？它又留下什么代价？** 年份用于定位代表性工作，各篇正文给出原始资料入口；同一技术常有更早的思想来源与后续变体。

这些路线在不同问题域中交叉发展。CNN、循环网络、注意力、树模型和检索系统都仍有适用场景；时间靠后的技术也不会自动在数据需求、计算成本和任务效果上全面占优。

| [[线性回归与逻辑回归]]：回归与概率建模的统计传统                         | 连续测量需要拟合；类别判断需要概率与阈值      | 参数化预测，定义残差或似然并估计参数         | 特征关系、模型假设与非线性边界   |
| [[经典机器学习方法]]：1995年 SVM、2001年随机森林等代表工作              | 单一线性边界难以适应各种数据几何与交互关系     | 邻域、概率分解、间隔、递归划分与集成提供不同归纳偏置 | 选型、特征、样本量与解释成本    |
| [[无监督学习与降维]]：多元统计与聚类传统                             | 大量数据没有标签；高维表示难以观察和压缩      | 按相似性分组，或寻找保留变化的低维方向        | 统计结构与实际任务意义可能不一致  |
| [[感知机]]：1958年感知机及后续多层网络                            | 自动分类需要可学习参数；单层模型受线性边界限制   | 感知机从误分类更新权重；隐藏层构造非线性表示     | 多层参数如何高效得到训练信号    |
| [[损失函数与梯度下降]]：1986年代表性多层网络论文                       | 输出误差不能直接告诉每个隐藏权重如何调整      | 沿计算图用链式法则复用局部导数            | 梯度有了之后仍需合适优化与数据   |
| [[神经网络优化与泛化]]：2014年 Adam／Dropout、2015年 BatchNorm 等 | 深层网络训练尺度不稳，训练好也可能过拟合      | 自适应步长、归一化、正则化和验证选择分别干预不同环节 | 超参数、分布变化与评价泄漏     |
| [[卷积神经网络]]：1980年 Neocognitron、2012年 AlexNet 等      | 图像展平后全连接参数多，空间邻近和重复模式难以利用 | 局部连接与权重共享形成层级视觉特征          | 感受野、长距离关系及变换鲁棒性   |
| [[残差网络]]：2015年 ResNet                              | 网络加深后，普通网络连训练误差也可能变差      | 恒等捷径让残差分支学习对输入的修正          | 梯度与优化仍可能困难，深度也有成本 |

感知机到多层网络，主要跨过了**表示能力**的门槛；反向传播与优化方法，处理的是**怎样把这些表示训练出来**；正则化和评价，处理的是**训练结果能否用于未见数据**。这几类问题应分别判断。

## 从序列记忆到语言系统

| 笔记与历史线索                                                                | 问题域与旧困难                         | 新机制带来的改变                          | 仍要解决的问题                   |
| ---------------------------------------------------------------------- | ------------------------------- | --------------------------------- | ------------------------- |
| [[循环神经网络]]：1990年 Elman 网络等                                             | 语言、传感器信号有顺序，固定窗口不便表达不断延续的历史     | 用共享递推和隐藏状态概括过去                    | 长期梯度传播与时间步串行依赖            |
| [[LSTM与GRU]]：1997年 LSTM、2000年遗忘门、2014年 GRU                             | 普通递推难以保留远处线索，也难以选择何时更新          | 门控调节保留、写入与输出，改善长期信息通路             | 固定状态容量和串行计算仍然存在           |
| [[词元化与向量嵌入]]：2003年神经语言模型、2013年 Word2Vec、2018年 BERT、2019年 Sentence-BERT | 离散编号没有可用距离，稀疏表示难以共享统计；检索又需要整句表示 | 从任务中学习向量；进一步区分输入词表、上下文表示和句向量      | 相似度的含义取决于训练目标，分词也影响处理单位   |
| [[注意力机制]]：2014年预印本／2015年会议的翻译注意力                                       | 编码器把长句压进固定摘要，解码器难以按当前需要访问不同位置   | 当前查询对全部候选打分，再聚合相关内容               | 打分成本、掩码、位置与证据解释           |
| [[Transformer]]：2017年原始编码器—解码器                                         | 循环结构限制序列内并行，远位置交流要经过许多时间步       | 用自注意力组织位置交互，配合前馈、位置、残差和归一化        | 密集注意力成本随长度平方增长，自回归生成仍逐步进行 |
| [[大语言模型的训练与生成]]：2020年 GPT-3、2022年 InstructGPT 等                        | 单任务专用模型迁移受限；续写目标与按指令帮助用户也有差距    | 大规模预训练提供通用模式，指令与偏好训练调整行为，解码选择具体输出 | 事实可靠性、上下文、资源和评价边界         |
| [[模型微调与LoRA]]：2021年 LoRA、2023年 QLoRA                                   | 为每个任务训练并保存全部大模型参数，显存与存储代价高      | 冻结基座，以低秩增量适配；量化基座还可进一步省存储         | 适配容量、训练数据及基座计算仍然需要        |
| [[检索增强生成]]：2020年 DPR 与 RAG 等                                           | 参数知识不便及时更新和追溯，生成模型难以直接访问私有新资料   | 在回答时检索外部证据，再把原文提供给生成器             | 检索相关不等于足以回答；引用和缺证据拒答需独立检验 |

其中有两条不同的瓶颈链：RNN → 门控主要改善**信息如何沿时间保存**；序列到序列 → 注意力主要改善**当前输出如何访问输入**。Transformer 进一步改变位置交互的计算组织。嵌入贯穿这些架构；LoRA 与 RAG 则分别处理参数适配和外部资料访问，可以组合使用。

## 从预测标签到生成样本与选择行动

| 笔记与历史线索                                   | 问题域与旧困难                            | 新机制带来的改变                          | 仍要解决的问题              |
| ----------------------------------------- | ---------------------------------- | --------------------------------- | -------------------- |
| [[变分自编码器与生成对抗网络]]：2013年 VAE 预印本、2014年 GAN | 重建训练数据不一定得到可直接采样的潜空间；复杂样本分布也难以显式建模 | VAE 用潜变量概率模型与变分目标；GAN 用对抗判别信号学习生成 | 后验近似、重建取舍、训练稳定性与模式覆盖 |
| [[扩散模型]]：2015年早期工作、2020年 DDPM             | 希望把复杂生成任务拆成可训练的小步骤，并改善生成质量与训练表现    | 规定逐步加噪过程，学习与噪声等级有关的去噪／反向分布        | 采样步数、计算成本、条件控制及数据需求  |
| [[强化学习基础]]：1992年 Q-learning、2013年 DQN 等   | 动作改变后续状态，正确行为往往没有逐步标签，奖励还可能延迟      | 以回报评价行动，通过交互学习价值或策略；深度网络扩展表示      | 探索代价、样本效率、稳定性及奖励设计   |

VAE、GAN 和扩散提供不同的生成学习目标，内部都可以使用神经网络组件。强化学习面对的是行动与后续后果，也可与语言模型训练结合；它与静态样本上的下一词元预测有不同的反馈结构。

# 技术关系

| 技术 | 处于什么层次 | 与其他技术的关系 |
|---|---|---|
| 感知机、MLP、CNN、RNN | 模型及架构 | 使用损失与优化算法学习参数 |
| 残差连接 | 网络结构组件 | 可用于 CNN、Transformer 和扩散网络 |
| 嵌入 | 数值表示与编码方法 | 为语言模型输入及语义检索提供向量 |
| 注意力 | 信息交互组件 | Transformer 的核心，也可结合 RNN、CNN |
| Transformer | 模型架构族 | 可构成语言模型、检索编码器和视觉模型 |
| 自监督学习 | 构造学习信号的方式 | 下一词元、遮盖预测与对比学习均可采用 |
| LoRA | 参数适配方法 | 可对 Transformer 的线性投影进行微调 |
| RAG | 检索与生成组成的系统 | 可组合嵌入模型、索引与语言模型 |
| VAE、GAN、扩散 | 生成建模方法 | 可以使用 MLP、CNN、注意力或 Transformer |
| 强化学习 | 交互式学习范式 | 可使用表格、神经网络和语言模型作为策略或价值模型 |

# 统一运行环境

全部项目使用下列固定环境。环境文件面向 Windows 64位，并固定 PyTorch 的 Python 3.10／CUDA 11.8构建，避免求解器混入 CPU 构建。`pytorch-cuda` 是 Conda 中的 CUDA 运行时配套包，并非 PyTorch 版本号；本组固定 PyTorch 2.2.2 与 torchvision 0.17.2。OpenCV 4.7.0 使用 Conda 包，避免将它误写成无法对应同一来源的 pip 安装命令。

## 环境文件

在任意工作目录创建以下三个文件。环境只需创建一次，之后各专题项目共用。基础科学计算库由 Conda 管理；模型工具在激活后通过受约束的 pip 命令补充。

### `environment.yml`

```yaml
# 统一环境名；激活命令和 VS Code 解释器选择都使用这个名称。
name: ml-ai-notes
# 列出包的来源；后面的渠道限定确保关键原生扩展使用验证过的构建。
channels:
  - pytorch
  - nvidia
  - conda-forge
  - defaults
# 基础运行环境，版本及构建保持固定；模型工具在激活环境后另行安装。
dependencies:
  # Python 的补丁版本也固定，统一为3.10.0。
  - python=3.10.0
  # PyTorch 的 Windows／Python 3.10／CUDA 11.8 构建，防止混入 CPU 构建。
  - pytorch::pytorch=2.2.2=py3.10_cuda11.8_cudnn8_0
  # 与 PyTorch 2.2.2 配套的视觉组件和 CUDA 构建。
  - pytorch::torchvision=0.17.2=py310_cu118
  # CUDA 运行时配套包；它不是 PyTorch 自身的版本号。
  - pytorch::pytorch-cuda=11.8
  # 数组、随机数据和数值运算。
  - numpy=1.23.5
  # 科学计算基础库，也是部分学习／图像库的依赖。
  - scipy=1.10.1
  # 图像处理库；对应 Python 导入名 skimage。
  - scikit-image=0.20.0
  # 绘图与图像文件输出。
  - matplotlib=3.7.1
  # 小波库；对应 Python 导入名 pywt。
  - pywavelets=1.4.1
  # 固定 OpenCV 的已验证构建；不要再混装 pip 的另一套 cv2。
  - conda-forge::opencv=4.7.0=py310h5588dad_1
  # 提供该 OpenCV／Qt 构建所需的16位正则接口，避免 DLL 缺失。
  - conda-forge::pcre2=10.42=h17e33f8_0
  # 经典机器学习、数据划分、预处理与评价工具。

  # 用于激活环境后安装带版本约束的模型工具。
  - pip=25.2
```

### `check_env.py`

把以下检查程序保存在工作目录，执行 `python check_env.py`：

```python
"""核对统一环境版本、Windows DLL 导入及 CPU／CUDA 基本运算。"""

# 标准库
import sys
import os
from pathlib import Path
import json
import importlib.metadata as metadata

# Windows 的 DLL 目录句柄需要保持存活；同时包含 Conda 的 MinGW 运行库。

# 1. 保持 DLL 目录句柄存活；该设置必须发生在 cv2 等本地扩展导入之前。
_dll_handles = []

# 仅在 Windows 注册 Conda 运行库目录；其他系统跳过这一分支。
if os.name == "nt":
    for folder in ["Library/bin", "Library/mingw-w64/bin", "Library/usr/bin"]:
        directory = Path(sys.prefix) / folder
        if directory.is_dir():
            _dll_handles.append(os.add_dll_directory(str(directory)))

# 2. 真实导入科学计算库和本地扩展，发现版本存在但 DLL 仍不可加载的情况。
# 第三方库（由统一环境提供）
import numpy as np
import scipy
import skimage
import matplotlib
import pywt
import cv2
import sklearn
import torch
import torchvision


def main():
    """核对统一环境版本、Windows DLL 导入及 CPU／CUDA 基本运算。

    按分段注释依次准备数据、执行计算并保存结果。
    """

    # 3. 直接列出要求的发行版版本号；metadata 使用安装包名而不是 import 别名。
    expected = {
        "numpy": "1.23.5",
        "scipy": "1.10.1",
        "scikit-image": "0.20.0",
        "matplotlib": "3.7.1",
        "PyWavelets": "1.4.1",
        "scikit-learn": "1.3.2",
        "torch": "2.2.2",
        "torchvision": "0.17.2",
        "transformers": "4.44.2",
        "sentence-transformers": "3.0.1",
        "huggingface-hub": "0.24.7",
        "tokenizers": "0.19.1",
        "safetensors": "0.4.5",
    }

    # 读取实际安装版本，不根据环境文件的声明推定安装成功。
    actual = {name: metadata.version(name) for name in expected}

    # Python 补丁版本也要匹配3.10.0，而不只是主／次版本一致。
    assert sys.version_info[:3] == (3, 10, 0), sys.version

    # PyTorch 可能带 +cu118 等构建后缀；先去掉后缀再比较基础版本号。
    for name, version in expected.items():
        assert actual[name].split("+")[0] == version, (name, actual[name], version)

    # 4. OpenCV 的模块版本及 PyTorch 所带 CUDA 运行时另行检查。
    assert cv2.__version__ == "4.7.0", cv2.__version__
    assert torch.version.cuda == "11.8", torch.version.cuda

    # 5. 实际执行 CPU 矩阵乘法，排除只完成 import 却无法运算的情况。
    assert torch.isfinite(torch.randn(3, 3) @ torch.randn(3, 3)).all()

    # 6. GPU 可用性取决于硬件和驱动；不可用时仍允许例程在 CPU 运行。
    gpu = torch.cuda.is_available()
    if gpu:
        # 有 CUDA 时再执行一次 GPU 矩阵乘法，并检查数值有限。
        x = torch.randn(3, 3, device="cuda")
        assert torch.isfinite(x @ x.T).all()

    # 7. 输出版本清单、CUDA运行时与实际设备信息，供复制环境后核对。
    print(
        json.dumps(
            {
                "python": sys.version.split()[0],
                "packages": actual,
                "opencv": cv2.__version__,
                "cuda_runtime": torch.version.cuda,
                "gpu_available": gpu,
                "gpu": torch.cuda.get_device_name(0) if gpu else None,
            },
            indent=2,
        )
    )


if __name__ == "__main__":
    main()
```

检查程序会在版本不符时立即指出。OpenCV 的 Qt 依赖需要带16位接口的 PCRE2，因此固定使用 Conda-forge 的10.42版本，避免混入同版本但仅含部分接口的其他渠道构建。检查程序还显式注册 Windows DLL 目录；其他单独使用 `cv2` 的程序遇到搜索路径问题时，可复用开头的目录注册代码。

CUDA 可用性还取决于显卡与驱动；没有可用 GPU 时，例程使用 CPU。配置文件包含 GPU 版 PyTorch，并不意味着每次运行都必须使用 GPU。

## 项目复原约定

1. 为每篇创建独立文件夹，按目录树创建手写文件。
2. 将标有文件路径的代码块完整复制到对应文件，保留缩进，保存为 UTF-8。
3. 激活统一环境，按该篇的运行命令执行；不需要把其他篇的辅助文件复制过来。
4. `outputs/` 由程序生成，模型检查点、指标和图片都保存在其中。
5. 神经网络项目支持 `--cpu`；只有 NumPy／scikit-learn 的项目直接运行，不接收该选项。

基础数据由代码生成或由 scikit-learn 内置提供。句向量检索、Qwen 推理与 RAG 首次需要下载公开模型；模型缓存由 Hugging Face 管理，同一账户后续运行可以复用。网络不可达时应保留原始错误，不能将下载失败解释为模型推理失败。
